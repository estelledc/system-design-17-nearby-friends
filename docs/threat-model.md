# Threat model

## Assets and trust boundaries

Even synthetic coordinates and social edges are treated as sensitive because the same shapes would be highly identifying in a real
system. Protected assets are bearer credentials, owner fingerprints, account/device/location/session identifiers, relationship
state, precise coordinates, request keys/digests, cursors, wake channels, and result bodies.

The HTTP caller, PostgreSQL, Redis, worker, process logs, CI, and any future WebSocket adapter are separate trust boundaries. A
mobile client's requested subscription is never an authorization source.

## Addressed threats

| Threat | v0.1 control | Residual boundary |
|---|---|---|
| caller asks for an arbitrary account's location | owner-bound account/session lookup plus mutual current relationship joins | full identity provider and credential revocation are absent |
| one side still says friend after the other revokes/blocks | both directional edges must be current `accepted` | moderation and social-graph ownership are absent |
| disabled sharer remains visible | disable transaction deletes presence and emits refresh events; every read rechecks policy | bytes generated by a pre-cutover in-flight read cannot be recalled |
| delayed device update resurrects location | one current generation, strict next sequence, atomic presence replacement | multi-device merge and attestation are deliberately unsupported |
| replay extends TTL or changes coordinates | owner/key intent digest replays stored result; drift conflicts | callers must preserve their stable key durably |
| stale cleanup/expiry notification authorizes old data | database time and `expires_at` are checked in every result query | polling is required to refresh a view with no mutation event |
| Pub/Sub disconnect loses truth | Redis contains only a generic hint; PostgreSQL cursor/view is authoritative | wake latency can increase until poll/reconnect |
| worker crash duplicates external effect | payload is idempotent upper sequence; drain cursor is idempotent | Pub/Sub itself remains at-most-once per publish attempt |
| cursor theft or cross-session replay | HMAC signature binds version, owner fingerprint, session, and sequence | secret rotation/session revocation workflow is absent |
| dense graph causes silent privacy omission | fanout/density limits abort atomically and visibly | global lock and relational fanout do not scale globally |
| ordinary telemetry leaks location/social data | logs use generic operations, status, bounded counts, and server-only evidence labels | database/CI/operator access controls are not modeled |

## Intentionally unaddressed high-risk areas

- real account verification, token issuance/revocation, session management, compromised accounts, and account recovery;
- informed consent, minors/guardians, stalking and coercive control, scraping, rate abuse, collusion, block evasion, and emergency
  response;
- GPS spoofing, sensor provenance, device compromise, attestation, background permission, and radio/battery behavior;
- encryption at rest, KMS rotation, field-level access, audit-console authorization, data-subject requests, retention law, and legal
  process;
- WebSocket authentication, origin policy, connection takeover, slow consumers, output buffers, DDoS, and load shedding;
- database/Redis failover, replication lag, backup/restore, multi-region conflict, supply-chain attestation, and production incident
  response.

Because those controls are absent, the lab must never ingest real people, credentials, social graphs, device IDs, or location
traces, and its green tests cannot be used as a safety or compliance approval.
